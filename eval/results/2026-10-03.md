## What failed, and what changed

- **Run 0**: the model wrote a skill instead of a script, announced work
  without calling a tool, and imported modules that do not exist. Authoring mode
  replaced the tools, the prompt and the budgets.
- **Run 1**: three tool tasks put their logic in the starter's `lib/example.ts`
  instead of the file the request named. `request_deploy` now refuses while the
  starter's placeholders remain, and the prompt says to use the request's
  exact names.
- **Run 2**: `tool-03` and `tool-04` ran out of turns: a `write_files` call
  whose `files` was a JSON string was answered "files is empty", and the model
  never saw why. The tool now reads that shape, and says what is wrong when it
  cannot. Two site tasks that passed in run 1 failed here: `site-02` answered
  400 to a valid JSON body, and `site-03`'s page answered 500. Neither could be
  caught by a test, because handlers cannot be imported from `main.ts`.

- **Run 4** (handlers testable): all four site tasks passed, including the two
  that failed in run 2, because a test now calls each handler with a request
  context and catches the wrong status or the 500. The remaining cost was the
  model sending `files` as a string that was not valid JSON (19 refused calls
  before the parser was made forgiving, 3 after). `tool-04` stopped with a
  handoff note after the same check failure three times: its `lib/dates.ts` had
  been written with its newlines escaped twice, so it did not compile. A file
  like that is now repaired when it is written (not yet re-run).

## Open

- The suite is noisy: `site-02` and `site-03` passed in run 1 and failed in run
  2 with the same code. Ten tasks run once say little; run each several times
  before comparing two versions.
- Phase 3 targets: 80% passed (run 4: 90%), 15 turns or fewer (14.2),
  under $0.10 (0.052), escalations that were needed fewer than 1 in 10 (1 in
  10, and it was warranted). Met on one run of ten tasks; run each task several
  times before trusting it.
- `edit_file` was refused 7 times for an `old_string` that was not in the file.
  The model edits from memory of a file it wrote; reading it first, or
  replacing a whole file with `write_file`, is the usual fix.
